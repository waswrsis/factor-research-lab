# 多专家因子发掘总体方案评估

评估日期：2026 年 10 月 3 日。评估对象：《多专家因子发掘与迭代训练总体方案》第 1 版。

本评估保持因子研究、两层评分与迭代训练的范围，只讨论总体设计。评估依据包括原报告全文、研究目标与训练架构及验证机制三个方向的独立审查，以及相关方法文献。本轮没有修改原报告，也没有执行训练或市场实验。

## 总体判断

报告的方向合理，模块之间没有发现明显的必然矛盾，适合作为研究蓝图继续推进。它已经较清楚地回答平台由什么组成，但对怎样认定发现了有效因子，仍需补齐评价对象和证据归属。

最重要的三个问题是：整体模型改善是否来自因子提供了额外信息；评分能支持哪个任务与哪个范围的结论；持续更新和结构搜索怎样产生新的独立证据。它们应在开放自主搜索前明确，无须现在选择具体网络、分数权重或统计阈值。

建议有条件推进小规模概念验证，并先修订这些总体口径。当前没有足够依据判断该结构一定优于简单模型，也不能估计它发现有效因子的成功概率。

| 评价方面 | 当前判断 |
| --- | --- |
| 范围与用户目标 | 一致，已经聚焦因子、评分和训练 |
| 模块划分与逻辑 | 基本合理，可组合也允许简化 |
| 因子发现的可检验性 | 部分具备，因子证据与模型证据尚需分开 |
| 评分的可解释与可比性 | 原则正确，仍缺少固定的评价上下文 |
| 持续训练与结构探索 | 技术路线可研究，跨版本兼容和验证资料流转未闭合 |
| 本地原型可行性 | 适合从少量任务与小模型验证，本轮未测资源和训练耗时 |
| 已有有效性证据 | 当前文件属于设计，没有新增实证结果 |

## 应当保留的设计

两层评分分开是合理的。因子长期质量、当下评分强弱和证据充分程度含义不同，原报告已经防止把它们混成一项胜率。

专家不全部承担价格预测，也符合当前研究目标。波动、关系和状态模块可以有独立研究用途；某模块只服务特定任务或条件，并不自动意味着它没有价值。

时间一致、标签成熟、历史输出不回写、验证资料用后登记和完整失败记录，都是报告已有的明确约束。原报告还承认自定义状态不能自证、低相关不等于新增信息、潜在表示坐标可能漂移。这些不应在评估中重新描述成完全遗漏的问题。

保留简单模型、固定组合、删除模块与同预算简单搜索的对照，也应继续执行。尤其要保留没有新增贡献、证据不足和简化结构等结果，避免平台以持续增加模块证明自身价值。

## 首要问题是区分因子贡献与模型性能

原报告的“因子质量评分”和“验证与反馈隔离”章节，允许评价单因子、专家、组合与整体模型，并要求匹配任务、资料和资源。这些要求有必要，但仍不能自动分辨成绩来自哪里。

可用下面的结构说明问题，其中 X 是当时可用资料，f 是因子生成器，g 是使用因子的任务模型：

```text
因子或表示 z = f(X)
研究输出 s = g(z)
```

如果 f 和 g 同时改变、同时训练，总体成绩提高可能来自更有用的表示，也可能来自 g 更强、整体容量增加或优化更容易。这个结果支持整套候选系统改善，不能直接证明某个因子可以独立复用。

建议在总体架构中分开两条评价线。第一条冻结已经学到的因子生成器，采用预先确定、可比的下游方法检验信息是否容易被使用；下游方法的类别、容量约束和训练程序可比，其参数允许按相同规则拟合。第二条允许整体重新训练，比较完整系统在实际研究任务上的表现。

第一条更接近因子表示的证据，第二条更接近系统性能的证据。两条结果可以不一致。一个表示若只有在特定复杂组合中有效，仍然可以保留，但应标记为该组合的组件；简单评价器无法利用它，也不足以证明它完全没有信息。

这项修正不要求所有因子具有固定公式，目的是准确说明成果属于单因子、因子组、潜在表示模块还是完整模型。

## 研究任务需要区分三种主张

原报告已经禁止状态自证和以重构成绩代替未来信息，但质量表仍将描述与预测并列。为防止系统选择容易获得高分的任务，应把下列用途分开记录。

| 研究用途 | 可以支持的结论 | 不能自动支持的结论 |
| --- | --- | --- |
| 描述或重构 | 能够表达当前或历史资料中的某种结构 | 具有未来预测信息 |
| 未来预测 | 相对可比参考方法，更好地预测指定未来目标 | 适用于其他任务或所有市场 |
| 辅助表示 | 在固定条件下帮助另一个预先确定的任务 | 单独就是通用预测因子 |

例如，专家将近期价格变化划为趋势与震荡，再准确重现这套分类，只能证明它完成了分类定义。若要主张该状态有新增研究价值，还需要与直接输入、简单变换或已有表示比较，确认这种表达额外解决了什么问题。

每项研究任务应在总体层面说明目标、简单参照、可用结果和允许作出的结论。对于辅助表示，需要注明它服务的外部任务；对于描述工具，可以保留其独立用途，但不把描述成功登记为预测发现。

这不会要求所有专家都预测价格。它只要求不同专家拥有与其职责一致的证据。

## 因子质量需要保留评价上下文

原报告已经强调增量价值。进一步需要明确：增量价值是相对于已有因子集合和使用方法的关系，不是一个因子永远不变的属性。

同一个因子加入集合甲可能有用，加入集合乙可能冗余。两个单独没有明显帮助的因子，也可能共同提供信息。若逐个按当前分数淘汰，系统可能失去这种互补关系。

建议把增量评价记为“候选因子或因子组，相对于某参照集合，在某任务、某下游方法及某训练规则下的改善”。档案记录这组上下文，允许互补模块组获得证据，不追求一个跨所有场景通用的因子排名。

删除实验也需要区分两种含义。直接拿掉一个模块、保持其余模型不变，主要观察当前系统对它的依赖；删除后重新训练，主要观察其作用能否被其他部分替代。前者还可能受到输入分布突然变化的影响，不能与后者共用一种贡献解释。

综合分可用于明确范围内的排序，但研究保留依据仍应查看质量向量及原始证据。准确度提高而稳定性下降的候选，不应只凭综合分更高就覆盖原版本；可以保留为另一种条件适用的候选。哪些质量维度允许权衡、哪些属于资格要求，是后续设计前应先确认的总体原则。

## 多专家应保留为可检验的架构假设

原报告已经要求与简单整体模型比较，因此不存在完全缺乏基线的问题。剩余张力在于，它同时将多类型专家写成确定路线。建议明确：模块化是研究组织方式，最终是否需要多个可学习专家，应由互补性和复现成本决定。

专家表中的类别还混合了不同维度。方向与波动是任务，量价及资金活动描述信息关系，市场状态常作为条件，开放表示则是一种学习方式。这些方向可以交叉，不宜直接转换成七个互斥的网络模块。

建议用三个问题说明一个专家：使用什么信息、学习什么关系、向哪些任务提供什么输出。可以保留便于沟通的名称，但不能用名称证明模块已经学会相应功能。

共享训练也应允许分流：某项任务受到其他任务影响时，可恢复专用模块或独立训练；多个专家实际作用重复时，先比较合并或删除。不要为了专家数量完整而强迫输出不相关，也不要把均匀组合权重当成有效协作。

多任务学习确实存在任务关系依赖和梯度干扰的研究依据，但这只能说明需要对照，不能证明本平台一定需要复杂专家结构。[MMoE 原研究](https://research.google/pubs/modeling-task-relationships-in-multi-task-learning-with-multi-gate-mixture-of-experts/)、[PCGrad 原论文](https://proceedings.neurips.cc/paper/2020/hash/3fe78a8acf5fda99de95303940a2420c-Abstract.html)

## 版本记录还需要组合兼容性

原报告正确指出，潜在表示重训后不能按同一维编号认定为同一个因子。然而，记录新旧版本并不能保证旧组合层还能正确使用新版输出。

即使维数没有改变，表示的方向、尺度或含义也可能变化。旧组合层可能仍然读取同样数量的数值，却误解其含义。历史评分保持不变解决的是追溯问题，兼容性解决的是新版如何继续使用的问题。

建议区分有明确计算含义的因子和整体交付的潜在表示模块。首版以预处理、专家、组合与评分解释组成完整版本包。一个部分改变后，需要重新确认相关组合；跨版本替换或表示对齐可以作为后续研究，不能默认成立。

同时应分开三类泛化证据：冻结因子生成器后适用于新环境；冻结生成器但允许下游方法适配；连生成器也在新环境重新训练。它们分别说明不同程度的迁移、适配与方法可重复性。后两类结果不能无条件继承为原因子的持续有效。

时间与标的也需要分开：已见标的的新时期、未参与训练的标的、未参与训练标的的新时期，支持不同的范围。某关系专家若使用了留出标的的无标签历史资料，应声明这一信息条件，不能称为完全没有见过该标的。

## 持续搜索需要管理证据的消耗

原报告要求完整记录候选，并规定独立验证资料一经查看即登记为已用。这些是正确基础，但自主搜索的范围还不只有网络参数。

研究任务、时间尺度、标的集合、市场状态子组、评分映射和停止时点，都可能成为搜索选择。即使每个候选单独看都遵守固定规则，连续试过许多组合后只展示最好的研究声明，仍然可能获得偶然高分。

因此建议把“研究声明”与模型版本一起登记：在什么输入条件下，哪种候选相对什么基准，改善哪个任务，结论适用于哪里。事先确定的声明与开发过程发现的声明分开；正式确认针对冻结的声明，而不是只锁定一个模型文件。

有限资料上的模型选择标准本身可能被过拟合，其偏差足以影响不同学习方法的比较。[Cawley 与 Talbot 原论文](https://www.jmlr.org/papers/v11/cawley10a.html) 自适应分析中反复查看验证分数也可能使验证集被过拟合；专门的复用机制有其统计条件，不能从普通留出验证自动继承保证。[Dwork 等原论文](https://arxiv.org/abs/1506.02629)

总体上需要明确开发资料、待确认资料、已消耗资料和真正新增成熟资料的流转。旧资料可以继续用于开发，但不能恢复成未见证据。新资料也不是无限资源，允许系统暂时积累证据而不发布新发现。

滚动学习另需区分学习与评价：按固定更新规则形成当时评分，结果成熟后评价，再按规则更新。评价对象是这套顺序学习过程，不要求参数永远冻结。结构比较则应固定更新规则和可用资料，避免将旧结构旧数据与新结构新数据的差异全部解释为架构进步。

agent 的候选应与相同条件下的简单搜索比较。随机搜索在部分标准神经架构搜索基准中具有竞争力，这支持设置强基线；那些基准不是金融数据，不能直接预测本项目中哪种搜索会获胜。[Li 与 Talwalkar 原论文](https://proceedings.mlr.press/v115/li20c.html)

## 数据资格影响可行性

原报告已经要求实际可用时间，但总体数据资格还应覆盖历史修订、回填、覆盖起始时间和当时存在的标的范围。今天下载到某个历史数值，不足以证明当时可以拿到同样版本。

建议每类数据进入研究前声明其历史可用性证据。原始版本、派生处理、标的集合和标签规则共同确定数据版本。无法重建当时信息的资料，可以明确用于探索，但不能支持当时可形成某评分的确认结论。

本地原型的首要工作量可能来自数据和证据状态管理，而不仅是网络计算：多任务结果成熟、版本依赖、候选尝试和资料使用状态会同时增长。这是基于架构的工作量判断，本轮没有进行硬件测量或工时估算。

小规模系统具有明确的工程路径。大范围数据、多个任务、联合训练、滚动更新和结构搜索同时开放，则会显著增加归因和复现难度。应按独立研究问题逐步开放能力，而不单纯以显存能否容纳作为范围依据。

## 应当能够否证的情形

以下是总体设计应当允许出现的研究结论，不是本轮已执行的测试。

| 观察到的情形 | 合理的解释或处理 |
| --- | --- |
| 简单整体模型与多专家表现相近 | 多专家尚未证明额外价值，允许采用简单形式 |
| 表示固定后没有改善，整体重训后改善 | 记录完整系统改善，不自动归为单因子信息增加 |
| 描述或重构分数很好，未来任务没有增量 | 保留描述用途，不登记为未来预测发现 |
| 两因子单独无明显作用，组合后有效 | 对组合建立证据，避免只按单因子排名淘汰 |
| 新版专家维数不变，但旧组合失效 | 属于兼容性问题，需要完整版本重新确认 |
| 开发评分持续改善，独立确认没有改善 | 不认定持续发现，检查搜索偏差与证据限制 |
| 重训后新标的表现好，冻结旧因子无帮助 | 支持方法可重现，尚不支持原模块直接迁移 |
| agent 搜索未优于简单搜索 | 保留简单搜索或缩减 agent 的研究职责 |

## 建议的修订优先级

优先补齐三个总体约定：明确发现对象及允许的结论；将表示评价与整体系评价分开；让质量评分携带任务、参照集合和训练方式等上下文。

接着明确完整版本的兼容性、迁移与重训证据的区别，以及开发到独立确认的数据流转。它们决定平台能否在连续迭代后仍然可信。

专家数量、具体网络、损失权重、更新时间和评分数值映射可以继续暂缓。单独依靠这些参数的细化，无法替代上述证据设计。

最终建议保留总体方向，先建立可清楚解释、可复现、可否证的最小因子研究循环。多专家、共享训练和结构搜索各自证明增量价值后再扩大。允许研究最终采用较简单的形式，是本方案实现目标的一部分。
