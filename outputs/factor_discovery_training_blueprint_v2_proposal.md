# 多专家因子发掘与迭代训练修订方案

第二版修订建议稿，2026 年 10 月 3 日。

本稿结合第一版总体方案、上一轮设计评估和用户提供的训练稳定性报告，补齐训练控制、因子评价和版本迭代之间的关系。继续以因子发掘、研究评分与迭代训练为范围，暂不规定具体网络规模、分数权重或更新周期，也不纳入持仓与交易执行。

核心改进是：保留多类型专家和两层研究评分，增加独立的训练管理与证据管理职责；用两条评价线区分因子表示的贡献与整套模型的表现；用完整版本包承接参数更新和结构变化。训练能够正常结束、满足停止条件、在新数据上有效、提供新增因子信息，分别记录。

本稿是待讨论的设计建议。原方案与评估报告保留，本次没有实施、训练、下载市场数据或复现附件中的数值实验。

## 如何吸收附件意见

用户附件针对旧版事件时间方案。其训练诊断思路可以推广，但事件任务的特定公式与旧版交易模块不应直接变成当前系统的通用要求。

| 附件内容 | 本稿处理 |
| --- | --- |
| 区分数值稳定、优化收敛与预测有效 | 采用，并进一步区分因子贡献与完整体系改善 |
| 输入处理、稳定损失、异常中止、检查点与停止原因 | 纳入统一训练管理职责 |
| 条件事件头的掩码、监督支持度与对数似然 | 作为事件任务专用约定，其他任务分别定义 |
| 固定特征与显式正则的简单基准 | 采用，限定证明所依赖的数学条件 |
| 多专家可能缺少梯度或功能重复 | 纳入专家诊断，允许合并、删除或独立训练 |
| 完整版本与失败回退 | 迁移到因子、组合和评分版本管理 |
| 旧版七类输出、轮数、种子数、优化器设置 | 不直接继承为新版的固定参数 |
| 经济有效性与持仓、行动价值模块 | 当前改为研究任务有效性与因子增量评价 |

附件自述的合成检查可以作为未来验证的参考思路。由于没有随附可核查的实验脚本和原始运行记录，本稿不将其登记为本项目已经完成的测试。相关公式和方法边界经过分析，不等于完整网络已经训练成功。

## 总体架构

研究主线保持为：时点一致的数据，经过专家生成因子表示，再由任务对应的组合与输出模块形成当前研究评分。真实结果成熟后，评价程序更新因子质量档案，并为后续研究提供开发反馈。

| 职责 | 负责的事情 | 主要产物 |
| --- | --- | --- |
| 数据与任务定义 | 确认可用信息、目标、结果成熟和评价范围 | 可追溯数据与任务版本 |
| 因子生成 | 从资料中学习或计算有用表示 | 单因子、因子组、潜在表示模块 |
| 任务组合与研究输出 | 按任务使用因子，不混合不同含义的评分 | 当前研究评分与预测记录 |
| 训练管理 | 按固定规则执行学习、检查异常并记录停止状态 | 训练状态、诊断和检查点 |
| 研究评价与证据管理 | 分开比较表示和体系，维护评价依据与资料状态 | 质量档案与限定范围的结论 |
| 研究 agent | 读取开发证据，提出可检验的参数、组合或结构修改 | 候选方案与对照安排 |

训练管理和证据管理是可检查的程序职责，不作为新的市场专家，也不与专家竞争研究评分。agent 提出候选，固定评价程序计算结果，版本管理程序决定候选是否满足预定的发布条件。

多专家仍是需要比较的架构选择。模块化方便研究，不要求最终模型一定保留多个神经专家；一个更简单的整体模型若达到相近效果，也可以成为被接受的成果。

## 任务与发现对象

每项任务说明使用什么信息、试图学习什么关系、输出供谁使用。方向、波动、量价关系、市场状态、标的联动和资金活动等可作为研究方向，但不把这些名称直接等同于互斥的网络模块。

任务分别声明其主张：描述或重构资料、预测指定未来目标，或者帮助另一个明确任务。描述任务可以有独立用途，但复述输入或识别自定义状态，不自动构成未来预测信息的发现。辅助表示需要与直接输入、简单变换或既有表示作可比检验。

发现对象分为明确因子、共同起效的因子组、整体交付的潜在表示，以及完整模型。证据属于哪一层就登记在哪一层；不因整个模型表现提高，就给所有内部维度增加因子质量分。

任务定义同时约定结果何时可用于训练。未成熟、不可观察、缺失，以及经过完整观察确实没有事件，是不同情况。保持对全部符合任务数据条件的研究输出记录与评分，不只给高分样本或后来表现好的子集提供反馈。不同条件下的表现可以单独报告，但要保留完整覆盖情况。

## 两层评分与四类状态

原有两层评分继续保留。当前研究评分表达当时的方向、波动、事件或关系判断；因子质量评分评价在特定任务和范围内的有效性、增量、稳定性、泛化与复杂度。概率、相对强弱和标准化位置分别解释，不能互换。

新增的训练记录不构成第三种市场评分，也不把数值健康加进因子质量综合分。四类状态分别存储，可以同时出现不同结论。

| 状态类别 | 核心问题 | 记录方式 |
| --- | --- | --- |
| 数值健康 | 输入、损失、梯度、参数和更新是否出现异常？ | 正常、异常中止、需要检查 |
| 优化停止 | 本次固定任务下为何结束？ | 达到预定停止条件、开发表现触发早停、预算耗尽、异常终止 |
| 样本外研究表现 | 在指定研究任务上，是否优于可比参照？ | 有支持、无改善、证据不足，并限定范围 |
| 因子贡献 | 改善可归属于哪个因子、组合或整体系统？ | 表示贡献、组合贡献、完整系统改善或尚不能归因 |

停止原因与诊断结论分别记录。例如预算耗尽时仍可能正常下降，也可能已经出现过拟合迹象；不能用一个含糊的“训练完成”覆盖两者。非凸网络达到工程停止条件，不称为已证明达到全局最优。

增量评价始终绑定候选、参照因子集合、任务、下游使用方法和训练规则。综合分只在同一评价口径内排序，质量向量、证据范围和不确定性仍是主记录。未通过数据资格或数值检查的结果，不能通过其他项目高分抵消。

## 训练管理与停止机制

训练管理器执行预先记录的学习程序，为所有模型提供一致的诊断框架。具体控制数值以后再定，但以下职责在总体设计中明确。

1. 输入与目标检查：验证信息时间、数据有效性、尺度处理和标签成熟规则；预处理仅使用允许的历史。
2. 任务损失检查：采用适合该任务的稳定计算方式，明确有效样本、掩码、聚合顺序和权重含义。
3. 更新诊断：观察分项损失、梯度、参数和实际更新幅度，检查专家输出尺度与获得监督的情况。
4. 异常处理：非有限损失、梯度或参数使本次运行明确失败；不能静默填零掩盖异常。修复后作为可追踪的新尝试。
5. 停止与保存：开发监控资料与最终确认资料隔离，按约定规则保存和选择检查点，记录选择依据及实际停止原因。
6. 输出与校准检查：核对评分含义、有效范围及校准状态；仅概率任务在需要时配置相应的独立校准，不能为所有评分强加一个温度参数。校准器只用事先指定的可用资料拟合，并在最终确认前冻结；拟合资料上的校准改善不能充当独立确认。

优化器配置、批次与归一化方式、精度策略、允许的调整和重试范围，都属于训练版本。梯度裁剪或学习率调整若使用，应有预定规则；它们可以帮助控制过程，但不能单独证明全网络收敛。

只看损失曲线不足以判断参数行为。在某些可分数据的无正则逻辑回归中，损失可以继续下降而参数规模持续增大，因此需要将参数行为与损失分开观察。该结论有特定假设，不用于宣称所有神经模型都会出现同样问题。[相关原论文](https://arxiv.org/abs/1710.10345)

## 条件任务与专家支持度

总损失可能主要由常见任务或常见状态贡献，不能用它证明所有任务都学会。每项任务需记录真正提供监督的样本覆盖、目标支持、分项表现和不同运行之间的差异。记录数量也不等于独立样本数，时间重叠和共同市场状态仍需考虑。

例如事件任务的后段方向，只能从此前没有事件且在该段发生事件的样本中获得直接方向监督。这个逻辑应推广为条件任务的通用要求：先判断哪些样本真的能回答该问题，再判断模型是否学到了规律。

支持不足时，可以限制适用范围、等待新增资料，或提出合并任务与简化结构的候选。不能只靠提高权重来宣称信息已经充足。任务或分段定义的改变属于新版本，要重新比较。

对专家检查其功能贡献、输出尺度、学习信号和使用情况。门控偏向一个专家可能是优化问题，也可能说明其他专家冗余，需要对照区分。允许合并、删除或恢复独立训练，不预设各专家必须均匀使用。

联合训练若使某个任务退化，应保留恢复专用表示或单独训练的路径。任务质量变化分别显示，不用平均损失掩盖退化。

## 简单基准与两条评价线

每项任务保留简单参考方法。对适合的分类或连续预测任务，可以采用固定特征上的正则线性模型，作为优化行为较容易解释的基准。它帮助区分数据问题、信息不足与复杂模型的训练问题，不承担证明神经模型收敛的职责。

| 评价线 | 保持什么可比 | 回答的问题 |
| --- | --- | --- |
| 固定表示评价 | 因子生成器冻结，下游方法类别、容量约束和拟合程序可比，参数按相同规则拟合 | 新表示对特定任务提供了多少可使用的信息？ |
| 完整体系评价 | 输入可用性、任务、资料与资源可比，允许完整模型按既定程序重训 | 完整候选系统是否改善？ |

固定表示评价比较明确的参照集合，也允许对因子组整体检验，避免只按单因子分数淘汰互补表示。简单下游方法无法使用某因子，不证明该因子完全没有信息；只能在特定复杂组合中有效的部分，可以以组合组件身份保留。

删除后不重训主要观察当前体系依赖，删除后重新训练主要观察可替代性，二者分别记录。新增输入、额外容量与结构变化分别说明，不能把它们的共同改善全部归给某个专家。

## 两个迭代循环

参数循环在固定资料、任务、结构和训练程序下运行：检查输入，执行学习，开发监控，按规则停止并选择检查点。它回答当前候选是否能被正常训练，以及达到什么优化状态。

研究循环使用开发证据提出候选：识别问题，修改因子或组合或结构，完成可比实验，冻结候选与研究声明，再进行独立确认。它回答修改是否增加了可验证的研究价值。两种循环都允许无改善、预算结束、归档和等待新证据。

滚动更新评价的是一套预先约定的顺序学习程序：先形成当时评分，结果成熟后评价，随后按规则更新。资料变化意味着目标函数可能变化，不要求一组参数永久停在某个值。

结构比较保持更新规则和可用资料可比。不能以旧结构旧资料对比新结构新资料，然后把成绩差额全部归为结构进步。若一次候选连带改变组合与训练，则按完整候选包评价，并限制对单个组件的归因。

## 版本包与候选隔离

完整版本包绑定数据与可用时间规则、预处理、任务与标签、因子生成器、组合与输出、评分解释、校准状态，以及训练和评价程序。可追溯不意味着兼容：新版表示维数相同，也可能无法被旧组合层正确使用。

候选单独训练和评价，符合既定发布条件后整体成为新的研究版本。失败候选保留诊断记录，不能覆盖已接受版本。过去因子值、评分与证据保持不可变，新版本仅影响之后的输出。

已接受版本也持续接受数据完整性、数值健康和适用范围检查。保留旧版不代表它永远有效；若旧版也失去支持，应明确标记停止发布相关评分或回到已经有适用证据的简单参照，不保证始终存在可用模型。

冻结模块在新环境有效、只适配下游后有效、整个生成器重新训练后有效，分别记录。它们支持不同的迁移或可重复性结论，新版不自动继承旧版的独立验证状态。

## 研究声明与证据流转

研究声明说明哪个对象相对什么参照，改善哪个任务，适用于什么资料和条件。模型、任务、时间尺度、标的集合、状态子组和评分映射的探索均进入研究记录，不能只登记网络参数。

时间切分同时检查训练标签的观察终点，不能使用在当时尚未成熟的未来结果。相邻预测窗口重叠、不同标的受到共同市场冲击，会使误差相关；样本数不能直接当作独立证据数，不确定性评价需保留这种相关结构。

自主选择预测期限或事件尺度时，先规定可比较的评价问题与选择规则，再用未见结果评价整个选择程序。不能在看到未来路径后，把每次预测改成最容易兑现的区间，也不能只凭缩小覆盖范围后的正确率提高判定因子进步。

资料区分开发、待确认、已查看及真正新增的成熟资料。独立确认一经查看，无论成功失败都登记已用；可继续用于开发，但不能恢复成未见证据。正在监控的确认结果也不能反馈给 agent 继续修改同一候选后再沿用原确认结论。

多数候选比较留在开发阶段，独立确认用于事先选定并冻结的候选与研究声明。确认时仍需考虑并列声明和反复确认造成的多重比较；保留搜索规模、失败候选和完整结果记录，避免把大量尝试中偶然出现的改善当作可靠发现。

数据进入确认研究前说明历史可用性，包括修订、回填和覆盖区间。无法重现当时信息的数据可用于明确标注的探索，但不支持当时可生成该评分的结论。

agent 可以读取开发诊断、提出候选、安排对照和建议简化。它不直接修改健康检查结果，不为某个候选重写评分尺子，也不把独立确认当开发反馈循环使用。评分或任务体系本身若需要修改，应另开研究版本并建立新的比较依据。

## 下一阶段应验证什么

推进顺序调整为：先使任务定义、简单基准和训练管理形成可复现循环，再加入少量专家进行两条评价，随后比较滚动更新，最后开放结构搜索。参数、组合和结构变化分开比较，不要求性能随版本编号单调上升。

| 验证环节 | 可以支持的结论 | 不能替代的证据 |
| --- | --- | --- |
| 公式与数值一致性检查 | 某项损失及其实现符合定义，极端输入下的行为可解释 | 完整模型训练稳定性 |
| 已知规律的受控资料检查 | 训练流程能在预设条件下学到可学习结构 | 真实市场的有效性 |
| 无信息资料检查 | 没有证据表明流程持续制造虚假样本外优势；需考虑随机波动 | 所有条件下绝不出现假阳性 |
| 固定候选真实资料评价 | 在指定任务与范围内的样本外表现 | 其他任务或环境的泛化 |
| 固定表示与完整体系对照 | 改善可归属于何种对象 | 经济因果或交易收益 |
| 顺序更新评价 | 既定更新程序在当时可用信息下的行为 | 永久收敛或未来表现保证 |

当前没有执行表中验证。这些环节用于形成后续实验问题，具体通过标准需要在正式实验前确定。

## 事件任务的数学边界

这一节只限定附件数学结论的适用范围，不把事件任务设为所有专家的默认目标。

若一个任务按多个时间段描述首次事件，每段的事件 logit 为 u，事件发生后的方向 logit 为 v，使用 sigmoid 映射为条件概率，则完整样本的首次事件似然可以分解为有效条件二分类项。对于事件发生于第 k 段、方向 y 的样本：

```text
ell_i = sum_{j < k} stable_softplus(u_ij)
        + stable_softplus(-u_ik)
        + BCEWithLogits(v_ik, y)
```

完整观察期内未发生事件的样本，损失是各段 stable_softplus(u_ij) 的和。事件后没有监督，方向仅在事件当段有监督。未成熟或缺失标签不按完整无事件处理；未定义或非有限的损失不能靠乘零掩码来清除。

训练使用稳定的库原语，不直接展开 log(1+exp(z))，也不先将一串小概率相乘后取对数。PyTorch 的 BCEWithLogitsLoss 将 sigmoid 与损失合并，利用稳定计算方式减少分步计算的数值问题。[官方文档](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BCEWithLogitsLoss.html)

对这个完整事件似然，先累加每个样本的有效项，再按样本平均。把各段分别按其有效样本数平均后求和，会改变各段相对权重；额外类别权重也可能改变原概率学习目标。不同研究任务之间怎样平衡损失，是另一个需要明确的训练约定，不能直接照搬事件内部的聚合规则。

未额外加权的二分类项对 logit 的梯度为 sigmoid(z)−y，绝对值不超过 1，二阶导不超过 1/4。这些性质不能证明完整非线性专家网络收敛，因为网络参数梯度还受到内部映射导数影响；对 logit 的凸性也不会自动变成对全部网络参数的凸性。其他任务损失需要分别分析。

附件建议的受限基准在以下条件下成立：特征有限且固定，标签和掩码固定，存在有效训练样本，所有线性参数及偏置都加入正的显式二次正则。目标可写为：

```text
F(w) = mean_i(ell_i(w)) + rho * ||w||^2 / 2,  rho > 0
```

对于上述线性事件 logit 目标，似然项凸且平滑，正则使目标强凸并具有唯一有限最优解。采用符合平滑条件的优化方法和步长，可建立该基准的全局收敛依据。这一结论不适用于共同学习特征的非线性网络；其他任务需确认自身损失的相应条件。某个条件头没有数据时，正则仍可能给出唯一解，但不能因此认定它学到了规律。

AdamW 的解耦权重衰减与上述显式二次正则目标不能直接等同，优化器名称、早停或裁剪均不构成完整网络的收敛证明。[AdamW 原论文](https://arxiv.org/abs/1711.05101)

## 修订后的目标

平台的目标明确为：生成可以研究的因子表示，让训练过程可诊断，让评分具有明确含义，让每次修改的贡献能够被验证，并让失败候选不破坏既有研究记录。

长期进步通过可重复的研究发现体现，允许模型保持不变、删减结构或暂时等待证据。下一步应优先补任务约定、训练管理和两条评价线，随后才选择具体参数与实现方式。
