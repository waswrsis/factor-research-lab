第五版：自动编写、拟合和审核因子公式

本版实现的是“无人逐轮干预”的研究循环。你先确定资料、预测任务、评价方法和预算；
运行期间由GPT提出公式、检查反馈并继续修改，训练器拟合参数，评价器决定候选是否留下。
训练仍使用已经成熟的任务标签，例如未来波动或事件结果。“无人逐轮干预”不等于
无标签学习，也不等于模型能够自行改变研究目标。

能够写什么

GPT提交的是结构化的因果算子程序：可以自由组合已提供的运算，形成新的表达式树，
而不是只从完整的现成指标列表中挑选。现有运算包括加减乘、安全除法、绝对值、
tanh、log1p(abs(x))、sqrt(abs(x)+epsilon)、过去滞后、滚动均值/标准差、EMA，
以及最后值、均值、标准差、最大值、最小值等窗口内汇总。

例如，可以写“标准化收益减去其EMA，再乘一个可学习增益，最后经过tanh”。EMA的
衰减参数和增益可分别声明上下界，交给梯度训练共同拟合。GPT可以修改公式结构和
参数初值/边界；连续参数的实际拟合由训练器完成，每个随机种子的拟合值都会保存。
公式输出随后进入现有的表示模块和任务预测头，候选评价针对完整模型。

输入是已注册特征的过去窗口，且已经使用训练资料拟合的均值和尺度完成标准化。
公式中的return_1h等名字对应标准化后的特征值，不能直接当作原始价格或百分比单位。
公式可以声明特征子集，不能自行读取未提供的数据、未来K线或其他样本。滞后只允许
指向过去；滚动运算缺少历史的开头位置会从汇总中排除；窗口不够时直接拒绝。

程序由固定的可信Torch解释器执行。GPT不能任意编写并运行Python、调用系统工具，
也不能在一次提案中发明并执行新的底层运算。source_listing只是编译器导出的可读
公式清单，不是可执行Python源码。

怎样自动继续

每次研究只看当前截止时间以前已经可用的输入和已经成熟的标签。GPT得到净化后的
开发资料包，包括过去提案、得分、受限错误类别，以及优化步数、梯度、实际参数更新
和权重继承等训练诊断。无效提案可在尝试次数内自动重试，下一次请求附带结构化拒绝
原因；训练完成后的结果也可进入后续研究轮次，供GPT重新分析和调整。

这是一名提案研究者对反馈的自动检查和修订；语法校验、实际训练、得分与升级门槛
仍由固定实现完成。GPT没有改写任务标签、时间切分、评分函数、影子观察期或升级
标准的权限。候选必须经过规定的后续影子比较，未达到门槛时保留现用模型。

成功的算子定义和开发结果会保存到本地。下一周期可以在预算内复活历史成功结构，
作为当前候选父结构重新训练和评分；旧得分不能直接充当当前表现。记忆按输入语义、
标的、窗口、可用时间和数据来源等上下文隔离，并不自动适用于所有市场。

开始使用

全部工作保留在D:/FactorResearch。先在PowerShell进入该目录：
  Set-Location D:/FactorResearch

查看入口说明，不启动训练或GPT调用：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Help

在新运行目录启动GPT提案闭环：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Run -Output runs/my-operator-v5 -Backend codex

入口默认使用config/discovery_v5.json、config/evolution_v5.json，资料目录为
data/discovery/2025-hourly，研究记忆为data/research_memory_v5.sqlite，设备为cpu。
它会安排环境目录并启动有预算的提案消费者，使用已有Codex登录；模型和推理设置为
gpt-6.1-sol/high。机器需要保持运行，远端服务仍受登录状态、用量和响应时间限制。

如需先使用规则提案器检查本地流程，另建运行目录：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Run -Output runs/my-operator-rules-v5 -Backend rules
rules生成受限公式，但不调用GPT，不能把它的结果称为GPT研究验收。

显式选择已有数据和协议的示例：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Run -Output runs/my-custom-operator-v5 -Config config/my-protocol.json -Policy config/my-policy.json -Data data/feeds/my-feed -Memory data/my-operator-memory.sqlite -Device cpu -Backend codex

启动前应检查自己的协议文件。默认示例仍使用2025年的既有开发资料；这些资料已经被
研究使用过，不能再次冒充未见的独立确认数据。旧日期协议不会自动研究当前行情。
实时资料的采集、实际接收时间和过去窗口预热要求见docs/DISCOVERY_DATA_V4.txt与
docs/EVOLUTION_GUIDE.txt；此简化入口没有watch参数。

恢复、检查与报告

在相同协议、政策、代码和资料语义下恢复原目录：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Resume -Output runs/my-operator-v5 -Backend codex

检查已经停止写入的运行：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Inspect -Output runs/my-operator-v5

导出报告：
  ./scripts/Start-AutonomousResearch.ps1 -Mode Report -Output runs/my-operator-v5 -ReportOutput outputs/my-operator-v5-report

恢复时需要保留之前显式指定的Config、Policy、Data、Memory等选项。改变源码、评价
协议或冻结身份后，应新建运行目录。旧固定模型和旧演化记录仍可作历史检查；它们
不会自动升级为第五版结果。中断的搜索记录消耗原预算槽，不能靠恢复获得无限重试。

在哪里查看公式和证据

运行目录中的research/cycle-*/candidate-*/operators.json保存完整程序、语义摘要、
可读公式和各随机种子的拟合参数；operator-library/*.json保存按程序校验值去重的
本地定义。跨轮复活主要依据受限开发记忆中的成功结构，不是扫描任意代码库。
每轮result.json和状态账本保存拟合、提案、得分及影子比较结果；worker目录与
worker.log保存提案消费者的尝试和停止情况。解释公式时应同时看输入标准化语义、
实际拟合参数和完整模型的评价，不能只看公式名字。

新运行归档factorlab源码和锁定依赖声明。历史检查校验保存的字节；恢复研究要求
当前源码与归档一致。归档不包含整个操作系统、驱动或Python二进制。

预算与已验证范围

演化轮数、每轮候选数、搜索时长、每次训练时长、模型参数量、GPT调用和重试次数都
有限制。默认政策最多3轮，每轮最多新拟合4个候选，采用2个训练随机种子；搜索上限
600秒，每个种子的拟合上限120秒、最多8个训练epoch。提案消费者最多288次请求、
最多运行3600秒，每个请求最多尝试3次，研究进程退出时会停止消费者。
公式还受节点数、深度、输出数、历史长度和数值约束。当前解释器最多64个
节点、12层、16个标量输出，输入过去窗口最多512步；实际窗口还受冻结协议及模块
时间尺度限制。超限或非有限数值会拒绝，有限中间幅值按公开上界截断。

到达预算后需要按已保存结果决定下一次独立研究安排，本版不是无限运行或无限增长
系统。增加原语、数据来源或修改评价器属于新的实现版本，需要另行测试和新建实验。

目前已通过488项完整测试，并完成真实GPT结合BTC/ETH/SOL历史小时行情的两轮开发验收：
7次提案全部完成，其中6次编写新程序；指标内部参数确有更新，历史结构也被重新引入拟合。
具体验收见outputs/OPERATOR_V5_ACCEPTANCE.txt。本次没有候选通过替换门槛，最终输出与
固定模型相同；未开展新的独立确认。不能据此声称发现了有效市场因子、改善了历史收益、
保证以后持续变好或具备实盘能力。
当前产物是研究表示、任务输出与证据，不提交交易。
