Resource-constrained service template
Generate, inspect, and explicitly install a NEW unit through existing user service
management; the script does not write ~/.config/systemd or call daemon-reload/start.
The command following -- must use THIS workspace .venv/bin/python and the fixed
whole-campaign guardian. Direct V7 CLI commands, including read-only inspect,
are deliberately rejected by unit-template. First freeze the new campaign using
the documented long-running controller; its campaign.json and campaign.sqlite
must already exist, and its canonical whole_tree_guard directory must be unused.
Generating a template does not authorize starting it before full acceptance.

  .venv/bin/python scripts/v7_linux_bootstrap.sh unit-template --workspace "$PWD" --old-unit fr-regression-active.service --scope user -- "$PWD/.venv/bin/python" -B "$PWD/scripts/v7_guard/campaign_guard_entry.py" guard "$PWD/runs/NEW_V7_CAMPAIGN" "$PWD/runs/NEW_V7_CAMPAIGN/whole_tree_guard" > runtime/v7-pilot.service

Template resource contract:
CPUQuota=25%; MemoryHigh=640M; MemoryMax=768M; MemorySwapMax=0; TasksMax=64;
CPU/Memory/TasksAccounting=yes; RuntimeMaxSec=7200; TimeoutStopSec=20;
KillMode=control-group; Restart=no; NoNewPrivileges=yes; UMask=0077.
The template contains no sudo, privilege escalation or resource-limit relaxation.
Its guard-exec reruns preflight and rejects an effective cgroup CPU quota above
25%, memory high/max above 640/768 MiB, nonzero swap allowance or pids above 64.
Systemd user controllers must actually enforce these properties; a printed unit
file alone is not evidence. If delegation is missing, stop and ask the operator
to resolve it without widening the frozen resource envelope.

Read-only resource receipt:
  .venv/bin/python scripts/v7_linux_bootstrap.sh resources
Run inside the service's cgroup. It records effective limits, memory.current,
memory.peak, memory.events, cpu.stat and pids.current. ExecStopPost prints the same
receipt to the journal before the cgroup disappears. Capture unit properties,
journal output and exit status as evidence; a Windows working-set measurement
cannot substitute for shared Linux cgroup memory (including proposer descendants).
memory.events oom/oom_kill increments, timeout, resource rejection or incomplete
output are failures/consumed attempts, never instructions to raise the limit.
